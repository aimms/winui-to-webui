# Operating WinUI_to_WebUI

[![Downloads](https://img.shields.io/github/downloads/aimms/winui-to-webui/total?style=for-the-badge&logo=github&labelColor=0B0B0C&color=2B37C9)](https://github.com/aimms/winui-to-webui/releases)
![aimms version](https://img.shields.io/badge/aimms-AIMMS_VERSION-BCEC48?style=for-the-badge&labelColor=0B0B0C&color=BCEC48)

This repository contains an aimms toolkit: **Operating WinUI_to_WebUI**. It lines up the WinUI pages of an aimms project with their WebUI equivalents, so you can see what carries over and what must be rebuilt.

## What this toolkit solves

Moving an application from the aimms WinUI to the aimms WebUI means rebuilding every
page by hand, and it is rarely clear which WinUI pages and objects have a WebUI
counterpart.

This toolkit lines up the WinUI pages of your project with their WebUI equivalents, so
you can see what carries over and what has to be rebuilt before you start.

## How to use this toolkit

To get the most out of this toolkit, we highly recommend reading our detailed step-by-step guide on the aimms How-to website:

**[Read the full article: WinUI to WebUI](https://how-to.aimms.com/Articles/711/711-winui-to-webui.html)**

### Prerequisites

- **aimms:** you will need aimms installed to run the model. [Download the free Academic Edition here](https://www.aimms.com/support/licensing/).
- **WebUI:** this toolkit runs in the aimms WebUI, for a modern, browser-based experience.
- **A WinUI project:** the application you want to move to the aimms WebUI, ready to open in aimms.

## Getting started

1. **Download the release:** go to the [Releases](https://github.com/aimms/winui-to-webui/releases) page and download the `.zip` file from the latest version.
2. **Open the project:** launch the `.aimms` file.
3. **Prepare:** open the WinUI project you want to migrate and note which pages it uses, as described in the article.
4. **Migrate:** work through the WinUI pages one by one and rebuild each in the **WebUI** with the matching widgets.
